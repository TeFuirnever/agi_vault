# 优化 CycleEdge.py 代码

## 问题分析
当前代码使用深度优先搜索(DFS)来检测图中的环路，然后找出形成环路的最后一条边。虽然功能正确，但存在以下可优化点：

1. **算法效率**：DFS 算法在最坏情况下的时间复杂度为 O(V+E)，其中 V 是节点数，E 是边数。对于大规模图，效率较低。
2. **数据结构**：使用固定大小的数组存储 visited 和 parent 信息，可能浪费空间，且不适合节点编号不连续的情况。
3. **代码结构**：整体逻辑可以更清晰，模块化程度可以提高。
4. **错误处理**：缺少输入验证，无法处理无效输入。

## 优化方案

### 1. 算法优化：使用 Union-Find（并查集）算法
Union-Find 算法更适合解决动态连接问题，时间复杂度接近 O(α(V))，其中 α 是阿克曼函数的反函数，实际运行中几乎是常数时间。

### 2. 数据结构优化
- 使用字典存储 Union-Find 结构，只存储实际存在的节点
- 移除不必要的数组，减少内存占用

### 3. 代码结构优化
- 将 Union-Find 逻辑封装成独立类
- 优化变量命名，提高代码可读性
- 模块化不同功能

### 4. 错误处理优化
- 添加输入验证，处理无效输入
- 添加适当的异常处理

## 具体实现步骤

1. **实现 Union-Find 类**：
   - 包含 find 和 union 方法
   - 支持路径压缩和按秩合并优化

2. **重构主函数逻辑**：
   - 读取输入边
   - 使用 Union-Find 算法边添加边检查环路
   - 当检测到环路时，直接返回当前边

3. **添加输入验证**：
   - 验证输入边数是否为正整数
   - 验证每条边的输入格式是否正确

4. **优化代码结构**：
   - 提高代码可读性
   - 添加适当的注释
   - 优化变量命名

## 预期效果

- 算法效率提高，特别是对于大规模图
- 代码结构更清晰，可读性更强
- 内存占用更合理
- 具备更好的错误处理能力

## 优化前后对比

| 优化前 | 优化后 |
|-------|-------|
| DFS 算法 | Union-Find 算法 |
| 时间复杂度 O(V+E) | 时间复杂度近乎 O(1) |
| 固定数组存储 | 动态字典存储 |
| 缺乏输入验证 | 完善的输入验证 |
| 代码结构较复杂 | 模块化设计，可读性强 |
